opencode-lossless is the OpenCode v2 adapter for a lossless context engine. It
mirrors every prompt, assistant reply, and tool exchange into a per-session
SQLite sidecar and summarizes the aged prefix into a DAG. The next request sees
that frontier, and the host receives it as its compaction checkpoint. The
original bytes stay addressable, so what compaction removed can be read back.

**Scope.** OpenCode v2 plugins only. The field splits into two categories,
compared separately because they solve different problems:

- **Context engines** rewrite or replace what the model sees when the window
  fills. They compete with this adapter.
- **Memory services** store derived memories, observations, or shared facts
  across sessions. They add a layer beside the context engine and do not own
  compaction.

A single matrix would mark most cells as not applicable and would compare a
verbatim context engine with a memory product. The two matrices keep the
categories separate.

Cells are read from source at the commits named in the verification note, never
from a project's README. This package's own cells are read from this repository.

## Where each one leads

**opencode-lossless.** Verbatim recall with provenance, a checkpoint that
replaces the host summary, a projection that stays cache-stable between cuts,
and a bundle with no runtime dependencies and no host SDK.

**magic-context.** The closest context peer. It adds project identity,
embeddings over history and memory, one store with compartments, and hidden
child sessions with cleanup tests.

**opencode-lossless-context.** It externalizes old blocks instead of summarizing
them, with a refcounted, content-addressed store and a real deletion path. Exact
recall without a DAG; the frontier grows with the number of distinct blocks.

**fast-opencode-compaction.** It prunes stale tool traffic from a typed decision
model, remembers decisions by `tool_use_id`, and counts dropped tool calls that
return. That counter is a safety signal this package does not measure.

**opencode-mem.** Project identity, a learned user profile, a memory tool with
curation modes, a web UI, and export/import. Its memory is derived, not the
transcript.

**claude-mem.** The most mature multi-harness memory service. Its search,
timeline, then observations chain is the closest analogue to grep, describe,
expand, and its v1 to v2 mapping is the clearest in the field.

**icm.** One SQLite file shared across many agents, fail-open by capability
probe, with a benchmark and a stated loss.

**hindsight.** Facts and entities rather than messages, with several retrieval
strategies in parallel.

## Not comparable

- **Context engine versus memory service.** This package and magic-context
  compete on what the model sees inside a session. Memory services compete on
  what survives between sessions. Running one of each is coherent; treating
  them as substitutes is not.
- **Verbatim recovery versus semantic recall.** This package returns the original
  bytes by address. Memory services return a summary, an observation, or a
  fact. A query with no token overlap with the original favors a memory service;
  an exact tool output does not.
- **No head-to-head benchmark.** No package here ships a benchmark of another.
  The comparison covers mechanisms read in source, not measured recall quality.

## When to pick which

| You want                                                                              | Reach for                 |
| ------------------------------------------------------------------------------------- | ------------------------- |
| A lossless transcript, a navigable frontier, and ownership of the compaction boundary | **opencode-lossless**     |
| The closest context alternative, with project memory and embeddings                   | magic-context             |
| Exact recall of externalized blocks, with no summarization                            | opencode-lossless-context |
| Cheap pruning of stale tool traffic without owning compaction                         | fast-opencode-compaction  |
| Curated project memory, a user profile, and a UI                                      | opencode-mem              |
| Multi-harness memory with progressive disclosure and observations                     | claude-mem                |
| One memory file shared across many agents                                             | icm                       |
| A fact and entity layer backed by an external vector database                         | hindsight                 |
