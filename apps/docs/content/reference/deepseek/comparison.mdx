deepseek-lossless is the DeepSeek harness adapter for a lossless context engine. It
mirrors every session event into a per-session SQLite sidecar and summarizes the aged
span into a DAG. The original bytes stay addressable, so what compaction removed
can be read back.

**Scope.** This page is DeepSeek only. The peer below is the harness's own replay-aware
basic compaction backend, with the pruner service and the token meter it drives. A
session runs one backend, so the cells compare what each one does with the same window.

Cells are read from the pinned packages, never from a project's README. This package's
own cells are read from this repository.

Last verified: 2026-10-25.

That date covers the peer cells and the audits named in the verification note,
and this package's own cells, measured from this repository (`packages/core`
plus `packages/deepseek`).

## One matrix on the same axes

## Where each one leads

**deepseek-lossless.** Verbatim recall with provenance, a DAG behind one checkpoint
per transaction, cross-session search and reads, and a resume path that rebuilds
continuity from the sidecar.

**The harness backend.** The closest peer and the default. It reuses the provider
prefix cache by construction, trims tool results without spending a model call,
frames checkpoints with merge rules and a goals section, prices pressure with
cache-bucket resolution, and recovers from overflow. None of that needs a store.

## By design, not missing

Gaps against this backend, each with the reason it stays that way:

- **No prefix-cache riding on summarizer calls.** The ladder sends one message per
  call, which cannot express prefix reuse. Deterministic input ordering ships as
  hygiene; cache-share claims wait on a replay prototype plus measured cache-read
  share plus a live key.
- **No pruner call on the adapter paths.** The seam runs the pruner before its own
  pressure and overflow measurement. The bracket paths summarize the selected span
  as stored; pruning live history would rewrite what the verbatim promise covers.
- **No curated goals section.** The checkpoint prompt captures evolving goals as
  prose. This package keeps the full transcript addressable, so goals are
  recoverable by address rather than carried as a section.
- **No child-session reader.** The harness has no hosted child session to borrow,
  so the reader runs in process with a step and token budget. Findings stay wrapped
  so raw transcript never enters the caller's context.

## Live proof

Run 2026-10-25 on the pinned harness with a live session: auto pressure stored 6
leaves plus 1 condensed node with a checkpoint replacement on the surface and one
`pass` metrics row. The summarizer wrote prose leaves plus a condensed parent with
billed usage; a depth-2 DAG of 61 summaries formed over 4 swaps. A fresh session
answered from aged history verbatim with cross-session entry citations. A defaults
quiet run mirrored 7 rows with 0 summaries and left the log untouched. Two boot
defects were fixed with tests (uninjectable session query degrades to
live-mirror-only; the cold message map re-derives from the live log). Suite
green across `vp check`, `tsc`, `bun run test`, and `bun run pack`.

Caveat, kept as a tuning follow-up rather than a loop defect: one model route was
pathologically verbose on rung prompts and hit the output cap where another route
wrote clean prose on the same prompts, so those nodes fell back mechanical.

## When to pick which

| You want                                                                                  | Reach for                |
| ----------------------------------------------------------------------------------------- | ------------------------ |
| A lossless transcript, a navigable DAG, recall by address, and cross-session search       | **deepseek-lossless**    |
| The harness default: cache-reusing summaries, model-free pruning, and overflow recovery   | the basic backend        |
